# Claros: research scan (arXiv and related venues)

Compiled 2026-10-03. Every arXiv ID below was checked against the arXiv API (title and date match).
GitHub repos were checked to exist (HTTP 200) on the same date. Items marked *(non-arXiv)* are classic
references cited from memory as background. They are not load-bearing for implementation.

Component legend (from `PRODUCT.md`): **perception** (screen → state), **brain/ledger** (unknowns
ledger, intent routing, question choice), **pause gate** (when to speak), **context tools** (look things up
before asking), **map builder** (Work Map induction), **merge** (multi-expert canonical flow),
**tutor** (learner loop, guardrail stops), **mastery** (learner model).

## 6. Multi-expert procedure merging and conflict detection

There is no direct arXiv paper on "merge N expert SOPs and surface contradictions". The closest work is task-graph learning from multiple demonstrations (video and robotics) plus process mining. The algorithm below is assembled from these.

| Paper | arXiv | Year | Contribution | Technique | Code |
|---|---|---|---|---|---|
| Differentiable Task Graph Learning | [2406.01486](https://arxiv.org/abs/2406.01486) | 2024 | Learns a **partial-order task graph** from multiple key-step sequences and uses it for online mistake detection. | Build the canonical flow as a DAG over aligned steps. Edge A→B means A precedes B in the demos. | [fpv-iplab/Differentiable-Task-Graph-Learning](https://github.com/fpv-iplab/Differentiable-Task-Graph-Learning) |
| Task Graph Maximum Likelihood Estimation | [2502.17753](https://arxiv.org/abs/2502.17753) | 2025 | MLE of edge weights from sequences. +14.5% F1 on CaptainCook4D. Improves online mistake detection. | For a hackathon, the **counting estimator** is enough: `P(A before B) = #seqs(A<B) / #seqs(A,B both present)`. Keep the edge if it is at least 0.9. Between 0.1 and 0.9, mark the pair as order-free (partial order, no conflict). | same repo |
| TaPeR | [2608.21035](https://arxiv.org/abs/2608.21035) | 2026 | Recovers **sparse precedence graphs from a handful of demos** using pairwise dependency probabilities plus filtering. | It fits our case of 2–3 experts. Initialize edges from pairwise precedence probabilities, then apply transitive reduction to get a minimal DAG. | — |
| UnityGraph (GPL) | [2311.03550](https://arxiv.org/abs/2311.03550) | 2023 | Graph over all videos of a task (intra- and inter-video). Clusters step embeddings to find shared key-steps. | **Step alignment across experts**: embed each step as `goal text + state signature + element label`, then cluster (agglomerative, cosine ≥ 0.8). Clusters are canonical steps. A singleton is an expert-specific step, which becomes a variant. | — |

**Conflict rule (our synthesis):** two experts' decision nodes are aligned (same cluster) and their **conditions overlap**, meaning the same case features, but the **chosen branch differs**. That is a `conflict`, and both experts get a "why" request. Same branch with different rationales is `consensus + multiple reasons`. Different order with no dependency is `variant`. Guardrails are unioned with attribution. Consensus strength is `#experts agreeing / #experts covering the node`.

### Evaluation metrics to adopt
- **Ask-F1** (HiL-Bench): measures "ask less, ask right" during capture.

- **pass^k** (τ-bench): consistency of tutor interventions.
- **Acceptance rate of interruptions** (ProactiveBench / PRISM): pause-gate quality.
